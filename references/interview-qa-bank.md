# 面试问答库（项目向）

> 本文件是面试准备的**项目向问答层**：回答"你做过什么、怎么做的、被追问怎么答"。
> **分工**：个人背景类问题（职业状态/离职/空窗/公司选择/职业规划/优劣势/薪资/Gap 应对）见 `interview-personal-qa.md`。
> 与 `interview-self-intro.md`（自我介绍）、`interview-strategy.md`（攻略）、`interview-prep-framework.md`（主流程）配合。
> ⚠️ 所有回答内容必须取自已确认选材的真实项目（弹药库）或用户确认的信息，禁止编造。

## §1 问题来源（四类）

| 来源 | 说明 | 数量 |
|------|------|------|
| JD 核心诉求 | 由 JD 拆解出的核心职责与要求逐条转化 | 2-3 |
| 弹药库项目 | 选中项目的关键动作（分层模型/AB实验/漏斗分析等）→ 深挖题 | 2-3 |
| Gap 项 | 适配度评估中标记的缺口（经验/领域/年限/规模） | 1-2 |
| 经历断层 | 空窗期、频繁跳槽、职级波动等（如有） | 1-2 |

**出题原则**：每个问题都必须指向"面试官想验证什么"，不为凑数造题。

### 1.1 三类问题与生成方法

| 类别 | 占比 | 考察 | 生成方法 |
|------|------|------|---------|
| 行为面试题 | 50%-60% | "你做过什么" | 提取 JD 中每条核心职责 → 转化为"请举一个你过往…的例子"；优先考察权重最高的 3-5 条 |
| 技术/专业题 | 20%-30% | "你会什么" | 提取 JD 必备技能 → 为每个关键词设计 1-2 题，**从基础到进阶分层** |
| 动机与文化匹配题 | 15%-20% | "你为什么来、合不合适" | 结合公司调研 + 职业转型/跳槽动机 + 对目标公司的了解 |

**行为题常见句式**："请分享一个你[做XX]的经历"、"举一个你[遇到XX情况]的例子"、"告诉我一次你[如何处理XX]的经历"。

**转化演示**（以产品经理 JD 为例）：
- JD 职责"负责产品需求分析与 PRD 撰写" → 面试题"请分享一次你从 0 到 1 定义产品需求的经历，包括你是如何识别需求的"
- JD 职责"推动跨部门协作落地产品" → 面试题"举一个你推动跨部门协作的例子，过程中遇到了什么阻力，如何解决"

**技术题分层设计**：

| 层次 | 考察 | 示例问法 |
|------|------|---------|
| 基础层 | 概念理解 | "你怎么理解 XX？" |
| 应用层 | 实操经验 | "你在实际工作中如何使用 XX？" |
| 深度层 | 取舍判断 | "XX 和 YY 的区别？什么场景用哪个？" |

**总量控制**：10-15 个（过多记不住）；三类配比大体遵循上表占比。

## §2 项目向问答

### 2.1 四类问题与回答结构

| 类型 | 示例 | 回答结构 |
|------|------|---------|
| 项目介绍 | "介绍一个你最有成就感的项目" | 口述版 STAR（见 interview-self-intro.md §3） |
| 业务深挖 | "你的用户分层模型怎么设计的？" | 方法 → 具体动作 → 数据结果 |
| Gap 应对 | "你没做过XX，怎么看？" | 承认 → 可迁移论证 → 学习路径 |
| 场景题 | "如果让你做XX业务，前三个月怎么做？" | 框架 + **必须关联真实项目经验** |

**业务深挖题的回答约束**：方法来自项目的 Action、数据来自 Result，**不得补充未做过的细节**（面试官一追问就穿帮）。

### 2.1.1 答题提纲结构

每个行为/项目题都按此结构准备答题提纲：

```
问题：[面试题原文]
建议引用经历：[弹药库中哪段项目]
STAR 提纲：
  S（情境）：[1-2 句背景]
  T（任务）：[1 句目标]
  A（行动）：[2-3 个要点，每点 1 句]
  R（结果）：[1 句量化成果]
关键数据点：[必须提及的数字]
避坑提醒：[可能被追问的弱点 + 应对话术]
```

> 答题提纲是**准备稿**（要点式）；实际口述时按 `interview-self-intro.md` §3 的口述版讲，不要照读提纲。

### 2.1.2 选择经历的原则

| 原则 | 说明 |
|------|------|
| 优先匹配 | 选与 JD 职责直接相关的经历 |
| 数据优先 | 选有量化成果的经历 |
| 深度优先 | 选能展开讲 2-3 分钟的经历 |
| 独占性 | 不同问题尽量用不同经历，避免重复 |
| 真实性 | 只选真实经历，不编造 |

### 2.2 场景题框架

| 场景类型 | 回答框架 | 关联经验要求 |
|---------|---------|-------------|
| 业务规划 | 现状分析 → 找抓手 → 建机制 | 关联类似业务的项目 |
| 指标分析 | 确认口径 → 拆解归因 → 验证假设 | 关联数据分析项目 |
| 产品设计 | 明确目标 → 用户/市场分析 → MVP 验证 | 关联 0-1 项目 |
| 增长策略 | 分析现状 → 找增长点 → 制定策略 | 关联增长项目 |
| 冲突处理 | 理解原因 → 寻求替代 → 影响决策 | 关联协作经验 |

**硬约束**：每个场景题回答必须包含"关联经验"段落，引用真实项目，否则是空谈。

### 2.3 追问预判（分级要求）

**分级原则**：4 层预判（L1-L4）工作量大（10-15 题 × 4 层），**只对核心题做完整版**，其余题简化：

| 题目范围 | 要求 |
|---------|------|
| **核心题（3-5 个）** | 完整四层预判 **+ 每层给出答案要点**（不只列问题） |
| 其余题 | 至少 L1（细节）+ L2（质疑）两层 |

**四层定义**：

| 层级 | 追问形式 | 准备来源 |
|------|---------|---------|
| L1 细节 | "具体怎么做的？分哪几层？" | 项目的 Action 具体步骤 |
| L2 质疑 | "为什么选这个方案？没考虑别的？" | 项目的决策逻辑（真实取舍） |
| L3 边界 | "如果数据量扩大 10 倍还适用吗？" | 展示思考，可关联其他项目 |
| L4 反思 | "如果重来，你会怎么改进？" | 项目的复盘沉淀（无则如实说） |

**输出要求**：预判不得只列问题——每层必须附**答案要点**（面试时能直接答）。

**准备约束**：L1/L2 必须来自真实动作；L3 展示思考深度；L4 无真实反思就坦诚承认，不编。

### 2.3.1 项目问答的口述版（必做）

答题提纲是**准备稿**（要点式），面试时要能开口讲——因此每个核心项目题除提纲外，必须生成**口述版**（口语句、有冲突转折，按 `interview-self-intro.md` §3 模板）。只给提纲、没有口述版 = 面试时用不上。

### 2.4 反向验证应对（面试官验真）

| 追问 | 面试官意图 | 应对 |
|------|-----------|------|
| "有没有人反对？怎么说服的？" | 验证是否真推进过 | 承认阻力 + 具体方法 + 结果 |
| "数据能验证吗？有看板吗？" | 验证成果真实性 | 数据 + 可追溯来源（口径、看板、周期） |
| "你最大的失误是什么？" | 验证自我认知 | 真实失误 + 影响 + 改进措施（不粉饰） |

### 2.5 不会回答的应对框架（5 步）

```
① 坦诚承认："{关键词}我没有直接负责过，这个我坦诚承认。"
② 理解转化：但我的理解是，{问题核心}本质是{转化为熟悉的领域}。
③ 展示思考：如果我来处理，会从几个方向切入：第一，{方向+理由}；第二，{方向+条件}。
④ 关联经验：我在{相关项目}做过类似的事，{具体经验}，这套方法可以迁移。
⑤ 承诺跟进：面试后我会深入学习{具体内容}，快速补齐。
```

**禁止**：❌"我不会但愿意学"（空洞）❌"这个我没做过"（放弃展示）❌硬编经历（追问必露）❌"这个不重要"（否定问题）。

### 2.6 Gap 领域的场景题

场景题若落在 Gap 领域（如无经验的业务），按 Gap 应对结构作答（见 `interview-personal-qa.md` §3），不硬找关联经验：

```
① 坦诚领域无直接经验
② 拆解问题本质，映射到自己熟悉的通用方法论
③ 给出可执行的切入路径（先做什么、验证什么）
④ 关联最接近的真实经验（即使行业不同，方法论可迁移）
```

**禁止**：为凑"关联经验"而把不相关项目硬扯进来（面试官能听出来）。
