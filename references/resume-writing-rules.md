# 简历写作规则（Phase 3 细则）

> 本文件是 `SKILL.md` Phase 3 的**完整写作规则**（13 条）。执行简历写作前必读。
> 配套：`references/anti-ai-guide.md`（去AI化/数据三要素/空洞词/脱敏）、`references/star-method-guide.md`（STAR/行为链条/证据三件套详解）、`references/resume-optimization-guide.md`（证据重排/模块优先级/压缩策略）。
> **素材来源**：Phase 2.5 确认的项目组合所对应的弹药库详情条目；弹药库只提供事实层，写入的每一条必须按 JD 重写，不得照抄原文。

1. **JD解码→行为层重写**：
   - 将 Phase 2 解码出的行为类别和具体动作，作为重写每段经历的骨架
   - 每段经历覆盖行为链条中的 2-3 个环节（启动→沟通→协调→冲突解决→决策推进→复盘沉淀）
   - 在经历中嵌入核心相关方信息（汇报对象、对接部门），证明操盘深度

2. **STAR法则重写**每段经历：
   - **S**ituation：简述背景（1句）
   - **T**ask：说明任务/目标（1句）
   - **A**ction：具体做了什么（1-2句，聚焦个人贡献，覆盖行为链条2-3环节）
   - **R**esult：量化成果（1句，必须含数据）
   - 每段经历控制在2-3个bullet point，单条不超过2行

3. **证据三件套验证**：同一公司经历整体描述需覆盖三层佐证：
   - 工作数据（百分比、金额、人数等量化成果）
   - 具体执行动作（设计了什么方案、搭建了什么体系）
   - 沉淀材料/可查记录（SOP文档、制度文件、项目存档）

4. **证据重排**（参考 `references/resume-optimization-guide.md`）：
   - 工作经历整体保持倒序排列（最近在前）
   - 单段工作内部：按JD关键词顺序重排bullet，JD重点强调的对应经历前置
   - 若最新工作与目标岗位弱相关但过往经历强匹配：新增独立「项目经历」板块，不受时间序限制，按JD匹配度排序

5. **简历结构（模块顺序/取舍/命名）**：按配置执行，可自由调整——
   - **优先级**：JSON `layout`（按 JD 微调）> `config/profile.yml` `resume_layout`（档案默认）> 内置默认顺序（header→summary→work_experience→education→skills）
   - **可用模块 id**：header / summary / work_experience / project_experience / education / skills
   - **project_experience**（独立「项目经历」板块）：用于个人项目或近期工作弱相关但过往经历强匹配时，不受时间序限制、按 JD 匹配度排序；个人项目【必须】放此板块，不得写进任何公司的 work_experience
   - **调整方式**：改列表顺序（如教育前置）；删模块即不输出；`{id, title}` 改名（如 summary→"个人优势"）；`{id, sep}` 控制该模块前分隔线
   - **新增模块**：JSON `extra_sections: [{title, bullets}]`（如"证书与培训""获奖经历"）；在其前放同名 `{id: <title>}` 可控制位置，否则追加到末尾
   - **书写建议**（决定 layout 怎么写）：学历优势突出（名校/海归）→ education 前置，学历普通但经历强 → 后置；基础技能与兴趣爱好绝不放靠前；强相关经历前置

6. **核心优势生成**（从维度库选材，不临场编造）：
   - 数据源：`config/profile.yml` `personal_advantage.dimensions`（每个维度含 content 素材 + applicable 适用岗标签）
   - **选 3-4 条（最多 4）**：按 JD 岗位类型命中 applicable 优先，无命中用「通用」维度兜底；AI 类 JD 必含一条 AI 相关维度
   - **标签锁定维度名**，不得新造维度或改维度名
   - content 是能力主张底稿，输出时按 JD 加工：调侧重 → 数据前置 → 注入 JD 关键词 → 压缩，不整段照搬；能力面描述为主，可点缀量化数据、不堆项目论据（论据留在工作经历）

7. **关键词优化**：
   - 将JD中的高频关键词自然融入简历正文（用于ATS筛选系统）
   - 专业技能里的工具/能力按 JD 相关性排序（JD 强调的排前）
   - 避免堆砌关键词，确保上下文通顺

8. **语态与文化匹配**：
   - 根据公司类型调整语态：互联网公司偏数据驱动、外企偏结果导向、国企偏稳重规范
   - 统一使用动词开头的bullet point

9. **AI三版本压缩**（参考 `references/resume-optimization-guide.md`）：
   - 生成极致精简版（确认删减下限）、原版完整保留（识别冗余）、适中优化版（交付基础）
   - 在适中版基础上逐条微调，拿捏语言压缩分寸

10. **工作经历项目分组**（公司行下按「▶ 项目N：」标题分组呈现，同公司 ≥2 个项目时使用）：
   - 各公司段的项目组装按 `config/profile.yml` 的 `project_grouping` 配置执行：
     - `fixed` 池：默认保留的固定项目，不随 JD 变化
     - `fixed_display`：从 fixed 池中实际呈现几个（如 `1-2`）；未配置则全部呈现。**只选 1 个时写充实；选多个时合并为「项目一」，但保持各项目逻辑边界清晰（不糊成一体）**
     - `incremental`：按 JD 相关性作为增量挑选，独立为后续项目条目
     - 未配置的公司段：其全部项目按 JD 匹配度自由选材，无固定保留项
   - 同段内项目**分开不混排**（固定主体在前，增量项目独立为后续条目）
   - ⚠️ **内容风格铁律**：每个项目下用 2-3 条**流畅 STAR 融合句**（数据内嵌），严禁拆成"背景/行动/成果"分段标签或短句碎片——保持简历读感连贯、信息饱满

11. **全经历 JD 语境化**（对工作经历**每一段**，不只选材主段）：
   - 先在 JD 背景下审视该段可调整的叙事侧重，**能真实贴合的就调**——数据不变，只把表述角度向 JD 靠；角度选取以 JD 关键词为准，对每段独立判断，不预设固定写法
   - **红线一·不编造**：只重写真实发生的事，"协助"不写成"主导"，没做过的动作/数据不加，不把弱相关硬说成强相关
   - **红线二·不强行调整**：经审视确实无法匹配 JD 的段，如实保留简洁表述即可，不为其调整而虚构关联、不夸大其价值
   - **适用范围**：适用于**所有公司段**（含时间较早的老公司），要求是**全段优化**——每段都尽量贴合 JD，而非只有主公司贴 JD

12. **专业技能生成**（静态工具栈 + 按 JD 裁剪，不临场编造）：
   - 数据源：`config/profile.yml` `tool_stack`（工具 / 能力 / 认证 三层，静态维护）
   - 输出：从 tool_stack 读取组装为「工具 | 能力 | 认证：证书」三层，LLM 仅按 JD **排序/裁剪**（JD 强调的工具/能力排前，明显无关的可删）
   - **不新增**：档案里没有的技能不得写入（防编造、防堆砌 JD 词）；动态补充（如空窗期说明）另行按需处理

13. **交付前自审**（写作完成后、进入 Phase 5 前逐项核对，不通过则回改）：
   - 选材组合与用户确认一致（无擅自增删）
   - 项目名/公司名/数据均能在弹药库找到出处；时间线与 `profile.yml` 一致
   - **量化数据规则分两档**（不与第 11 条打架）：
     - 与 JD 相关的强/中相关段 → **必须含量化数据**（数据三要素，见 `anti-ai-guide.md` §3）
     - 按第 11 条红线二判定「无法匹配 JD、如实简洁保留」的弱相关段 → **豁免含量化要求**，保持简洁即可，不得为凑数据硬塞内容
   - 无空洞词/黑话超限（词表见 `references/anti-ai-guide.md` §2）
   - 正文为流畅融合句，无分段标签、无碎片句、无照抄弹药库原文
   - 结果以「[自审] ✅ 全部通过」或「❌ 未通过: {问题列表}」输出，未通过则回改后再审
