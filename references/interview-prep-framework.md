# 面试准备框架（主流程）

> 面试准备的**主流程与总览**。详细方法拆分在：
> `interview-self-intro.md`（人设/自我介绍/口语化/钩子）、`interview-qa-bank.md`（出题方法/项目向问答）、`interview-personal-qa.md`（职业状态/个人向问答/Gap 应对）、`interview-strategy.md`（JD 翻译表/招聘背景/反问/调研/注意事项/心态）、`interview-story-bank.md`（故事沉淀）、`interview-question-bank.md`（按岗位类型分层的问题库）。
> 所有内容必须基于真实素材（弹药库 / profile.yml / 用户确认），禁止编造。

## 核心目标

基于 JD 与真实经历，生成针对性面试方案。旧体系的四项产出映射到本流程：

| 旧产出 | 本流程位置 |
|--------|-----------|
| 高概率面试问题预测 | Step 4 项目问答 + Step 5 个人问答（10-15 个，三类配比见 `interview-qa-bank.md` §1.1） |
| STAR 结构化答题提纲 | `interview-qa-bank.md` §2.1.1 提纲结构 + §2.3 追问预判（分级） |
| 向面试官提问清单 | `interview-strategy.md` §3（反问库 + 提问设计原则 + 类型参考） |
| 面试注意事项 | `interview-strategy.md` §6（着装/文化匹配/避坑） |

流程：定位人设 → 打磨故事 → 多版本自我介绍 → 预测问答（含追问预判）→ 攻略与反问 → 输出 MD。

## 输入（读取顺序）

| 文件 | 用途 |
|------|------|
| 本岗位 JD + Phase 2 拆解结果 | 核心诉求、关键词、适配度与 Gap |
| `references/project-library.md` | 选中项目的事实层（S/T/A/R 素材） |
| `config/profile.yml` | career_stages（职业路径）、personal_advantage（优劣势）、tool_stack |
| `references/interview-story-bank.md` | 已有 STAR+R 故事（优先复用） |
| `references/interview-question-bank.md` | **该岗位类型的高频题与盲区题**（反哺出题，见 Step 0） |
| Phase 2 公司调研结果 | 回答"为什么选我们"、反问 |

## 执行流程

### Step 0: 前置盘点（输入准备）
1. **继承 Phase 2 结果**：适配度匹配矩阵、Gap 项、公司调研——这些已在简历流程产出，不重做
2. **职业状态推导**：按 `interview-personal-qa.md` §1.1 判定当前职业状态，并做时间线连续性检查（§1.2）——这是后续自我介绍/个人问答的基础
3. **生成 Gap 应对策略**：按 `interview-personal-qa.md` §3 为每个 Gap 项准备应对结构
4. **读取问题库**（`interview-question-bank.md`）：判定本次 JD 的岗位类型 → 取该类型高频题 + 通用题（本次必覆盖）+ 该类型盲区题（本次必补）——**不同类型的高频题仅供参考，不硬套**
5. **读取故事银行**，比对已有故事与本次选中项目的匹配度

### Step 1: 人设设计
按 `interview-self-intro.md` §1 生成价值标题，并用项目证据验证；**必做两项自洽检查**：
- 人设关键词均有项目证据
- **人设不与适配度矩阵的 Gap 项矛盾**（如在 Gap 领域不得自称"XX 专家"）

### Step 2: 故事选择与口语化
优先从 `interview-story-bank.md` 匹配已有故事；无匹配则从选中项目构建，按 §3 打磨为**口述版**（口语、有冲突转折、有记忆点金句）。本次现构的口述版**经用户确认后可沉淀回故事银行**（详见其 §与选材的对接）。

### Step 3: 自我介绍多版本
按 §2 生成 1/2/3 分钟三版 + 面向 HR/业务/高管的差异化版本；嵌入职业路径叙事与钩子（每版 ≥2 个）。

### Step 4: 项目内容问答
按 `interview-qa-bank.md` §1-§2 出题并作答：四类问题（项目介绍/业务深挖/Gap/场景题）+ 追问预判（核心题完整 L1-L4，其余 L1-L2）+ 反向验证应对 + 不会回答的 5 步框架 + 核心题口述版。
> **出题反哺**：问题库中该岗位类型的**高频题必覆盖**、**盲区题必补**（Step 0 已取，见 `interview-question-bank.md` §5）。

### Step 5: 个人内容问答
按 `interview-personal-qa.md` §2-§3 生成：离职原因/空窗期（含 §1 职业状态结论）/公司选择/职业路径/职业规划/优劣势/薪资 + Gap 应对结构。

### Step 6: 面试攻略
按 `interview-strategy.md` 生成：JD 关键词翻译表（§1）、招聘背景分析（§2）、反问问题库（§3，含提问设计原则）、面试心态（§5）、面试注意事项（§6，着装/文化匹配/避坑）、面试前检查清单（§7）。

### Step 7: 公司调研摘要
按 `interview-strategy.md` §4 提炼 3-5 条可自然引用的公司信息（真实可查，标注来源）。

### Step 8: 输出

```
output/<公司>/<岗位>/interview_prep.md
```

文件结构：

```markdown
# 面试准备 - {公司} {岗位}
生成时间：{日期}

## 一、岗位适配与人设定位
- 价值标题 + 人设验证（含与 Gap 的自洽检查）
- 匹配度矩阵（继承 Phase 2 结果）
- **当前职业状态与时间线口径**（含非雇佣期说明）
- Gap 应对策略

## 二、自我介绍（多版本逐字稿）
- 1/2/3 分钟版；HR/业务/高管版；钩子清单

## 三、项目内容问答
- 项目介绍 / 业务深挖 / Gap 应对 / 场景题
- 每题含：追问预判（L1-L4）、反向验证应对
- 不会回答的应对框架

## 四、个人内容问答
- 离职/空窗/公司选择/职业路径/规划/优劣势/薪资

## 五、面试攻略
- JD 关键词翻译表 / 招聘背景分析 / 反问库 / 面试心态 / 面试前检查清单

## 六、公司调研摘要
- 3-5 条（含来源）

## 七、待补充事项
- 需用户补充的真实素材（如软素质故事）
```

## 问题分类参考（出题视角）

| 类别 | 考察 | 数量占比 |
|------|------|---------|
| 行为/项目题 | "你做过什么" | 50%-60% |
| 技术/专业题 | "你会什么" | 20%-30% |
| 动机与文化题 | "你为什么来、合不合适" | 15%-20% |

出题不追求数量，问题总量控制在 10-15 个（过多记不住），每题都要指向"面试官想验证什么"。

## 真实性红线

| 禁止 | 正确做法 |
|------|---------|
| 编造项目/经历 | 只用弹药库与用户确认的真实素材 |
| 捏造数据成果 | 数据与弹药库一致 |
| 编造软素质故事 | 标"需补充"，引导用户提供 |
| 场景题脱离经验空谈 | 必须关联真实项目 |
| 劣势用致命项/陈词滥调 | 选安全劣势 + 具体改进措施 |

## 输出前自审（输出质量检查清单）

**内容与真实性**：
- [ ] 面试问题覆盖 JD 前 5 项核心职责；总量 10-15 个且两类维度配比合理
- [ ] 每个行为/项目题都有 STAR 答题提纲 + 量化数据点
- [ ] 提纲引用的经历均为真实素材（弹药库）；**关键数据/细节均有来源标注，无自行补充**
- [ ] 人设每个关键词都有项目证据，**且不与 Gap 项矛盾**
- [ ] **当前职业状态已判定；非雇佣期/空窗已生成说明话术**
- [ ] 自我介绍为**口述版**（口语、有冲突转折），非简历书面语罗列
- [ ] **核心题（3-5 个）含完整四层追问预判且给出答案**；其余题至少含 L1-L2
- [ ] 核心项目问答除提纲外，另有可直接开口的**口述版**
- [ ] 覆盖 Gap 项（含应对结构）与个人向问题（含职业状态相关）
- [ ] **问题库该岗位类型的高频题已覆盖、盲区题已补**（不同类型高频未硬套）
- [ ] 软素质/无素材项已标"需补充"

**攻略与提问**：
- [ ] 含 JD 关键词翻译表（匹配类型不夸大：线索转化≠支付转化/复购）
- [ ] 反问覆盖将面对的全部面试官角色（含 HR），不少于 3 个
- [ ] 注意事项覆盖着装、文化匹配、避坑三个维度
- [ ] 含面试前检查清单

**输出**：结果以「[自审] ✅ 全部通过」或「❌ 未通过: {问题列表}」输出。
