# 面试个人向问答（背景·动机·状态）

> 本文件是面试准备的**个人向层**：回答"你是谁、什么状态、为什么来、要多少"。
> 与 `interview-qa-bank.md`（项目向问答）分工：本文件管个人背景类问题，项目向问题去前一个文件。
> 与 `interview-self-intro.md`、`interview-strategy.md`、`interview-prep-framework.md` 配合。
> ⚠️ 所有内容必须基于真实情况（profile.yml / 用户确认），禁止编造。

## §1 职业状态处理（贯穿全流程）

> 面试官必问"你现在是什么状态、上家什么时候走的"，此处先确定口径，其他环节（自我介绍/个人问答/翻译表）都引用它。

### 1.1 推导当前职业状态

从 `config/profile.yml` 的 `employment_status` + `career_stages` 最后一段推导：

| 状态 | 判定依据 | 处理 |
|------|---------|------|
| 在职 | 最后一段 period 为"至今"且为公司 | 无需空窗说明；离职原因改为"为什么想看新机会" |
| 离职待业 | `employment_status=已离职` + 最后一段已结束 | 必须准备空窗说明（见 1.2） |
| 个人项目/自由职业期 | 最后一段为"个人项目"或非雇佣性质 | 单列为"个人项目期"说明，**不标为空窗** |
| 进修/家庭期 | 用户确认 | 按 1.2 原因分类表述 |

### 1.2 非雇佣期说明（个人项目/空窗）

**时间线连续性检查**（必做）：逐段核对 `career_stages` 的 period，计算相邻两段间隔；**间隔 > 3 个月**即需处理（不论是否在 career_stages 中有"个人项目"记录）。

| 间隔时长 | 处理 |
|---------|------|
| ≤ 3 个月 | 不处理（正常过渡） |
| > 3 个月 | 必须生成说明话术 |

**说明结构**：
```
【承认】我在 {时间段} 结束了 {上一份工作}，到 {现在/下一份} 之间有一段时间。
【主体】这段时间我在做 {个人项目/进修/家庭事务}，{具体做了什么 + 产出}。
【衔接】现在我已经 {准备好/完成了什么}，希望回到 {目标方向}。
```

**个人项目期的特殊优势**：若期间有真实产出（如独立完成的产品/项目），**优先表述为能力证明而非"待业"**——如"这段时间我独立完成了 XX 产品从 0 到 1，实践了 XX 能力"。

**追问预判**（非雇佣期必被追问）：

| 追问 | 应对 |
|------|------|
| "这一年为什么没上班？" | 上述说明结构 |
| "个人项目具体做了什么？" | 项目事实（弹药库中个人项目条目） |
| "为什么不继续做下去/找其他工作？" | 说明职业选择逻辑，不贬低项目也不掩饰 |
| "这段时间有没有面试其他公司？" | 如实答，强调最终选择 |

## §2 个人向问答

通用问题，需结合 profile.yml 与真实情况作答。

| 类型 | 常见问法 | 数据来源 | 要点 |
|------|---------|---------|------|
| 离职原因 | "为什么从上家离职？" | profile.yml employment_status + 真实原因 | 不抱怨前公司、不谈薪资低/人际/加班 |
| 空窗期 | "你为什么有段时间没有工作？" | profile.yml 时间线（如有断档） | 承认 + 正面化 + 证明已准备好 |
| 公司选择 | "为什么选择我们公司？" | 公司调研（Phase 2）+ JD | 体现做过功课，非海投 |
| 职业路径 | "你的职业发展路径是怎样的？" | career_stages | 起点 → 转型 → 现状 → 与岗位契合 |
| 职业规划 | "你的职业规划是什么？" | JD 方向 + 真实意向 | 与岗位方向一致、路径可行 |
| 工作环境 | "你期望的工作环境是什么样的？" | 公司调研 + 真实偏好 | 与目标公司文化契合 |
| 优劣势 | "你的优势/劣势是什么？" | personal_advantage 维度 + 真实 Gap | 优势有证据；劣势选"安全劣势"+ 改进措施 |
| 薪资 | "你的期望薪资是多少？" | 用户真实预期 | 不先报价；给区间；强调综合考量 |

### 2.1 离职/空窗表述原则

| 场景 | 表述结构 |
|------|---------|
| 主动离职 | 承认收获 + 说明诉求变化 + 未来导向 |
| 被动/裁员 | 客观陈述（业务调整/优化）+ 能力证明 + 积极转向 |
| 空窗期 | 承认 + 说明原因 + 期间做了什么 + 证明准备状态 |

**避免**：抱怨前公司、说薪资低、说人际复杂、说加班多；空窗期不要含糊其辞。

### 2.2 优势必须带证据

每条优势 = 能力主张 + 真实项目证据 + 数据。优势与劣势不得互相矛盾。

### 2.3 劣势选择原则

选**不影响核心工作的安全劣势**（如"某工具使用较少"、"某领域经验较少"），并给出**具体改进措施**。

**避免**：致命缺点（抗压差/常迟到）、陈词滥调（"我太追求完美"）、JD 核心要求项上的劣势。

## §3 Gap 应对结构

适配度评估中标记的缺口，按类型准备话术：

| Gap 类型 | 应对结构 |
|---------|---------|
| 经验 Gap | 承认 + 经验密度/可迁移能力论证 + 学习计划 |
| 领域 Gap | 承认 + 底层方法论通用性论证 + 快速上手路径 |
| 年限 Gap | 承认 + 成果密度证明 + 定位务实表态 |
| 技能 Gap | 承认 + 相邻技能 + 具体补课计划与时间 |

**红线**：只承认、论证、给路径；不虚报做过、不贬低 Gap 的重要性。
