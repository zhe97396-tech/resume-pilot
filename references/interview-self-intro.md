# 面试自我介绍与人设设计

> 本文件是面试准备的**自我表达层**：人设定位、自我介绍多版本、口语化打磨、钩子设计。
> 与 `interview-prep-framework.md`（主流程）、`interview-qa-bank.md`（项目向问答）、`interview-personal-qa.md`（个人向问答）、`interview-strategy.md`（攻略）配合使用。
> ⚠️ 教学对照示例均为虚构，仅供理解方法，严禁套用真实素材。

## §1 人设设计（面试定位）

面试官在开场 1 分钟内形成的印象，决定后续所有问题的解读角度。人设 = 一份简历的**核心能力主张**，由"面试官能记住的一句话"承载。

### 1.1 价值标题公式

```
价值标题 = 我是帮助[目标业务/客户]解决[核心问题]的[身份定位]，实现了[量化结果]
```

**元素提取来源**（全部取自已确认的选材结果与弹药库，不自造）：

| 元素 | 来源 |
|------|------|
| 目标业务/客户 | JD 的业务领域 + 弹药库中与之匹配的项目 |
| 核心问题 | 由 JD 核心职责推断（如"推荐策略"→匹配效率问题，"商业化"→变现效率问题） |
| 身份定位 | profile.yml 维度库中命中的能力维度（如"用户增长操盘力"→增长产品专家） |
| 量化结果 | 弹药库中该项目最亮眼的真实数据 |

### 1.2 人设验证（必做）

人设的每个关键词都必须有项目证据，否则调整表述或降级：

| 人设关键词 | 证明项目（弹药库编号） | 证明数据 |
|-----------|---------------------|---------|
| （逐条填写） | | |

**验证失败处理**：关键词无项目支撑 → 换一个有支撑的表述，不硬吹。

## §2 自我介绍多版本

### 2.1 时长版本

| 版本 | 时长 | 结构 |
|------|------|------|
| 精简版 | 1 分钟 | 人设(10s) + 核心成果(40s) + 引导(10s) |
| 标准版 | 2 分钟 | 人设(15s) + 专业硬核(50s) + 软素质(40s) + 引导(15s) |
| 完整版 | 3 分钟 | 人设(20s) + 专业硬核(60s) + 软素质(50s) + 未来方向(30s) + 引导(20s) |

### 2.2 面向不同面试官的版本

| 面试官 | 关注点 | 侧重调整 |
|--------|-------|---------|
| HR | 匹配度、稳定性、文化适配 | 简化技术细节、突出成果与协作、强调长期意愿 |
| 业务负责人 | 解决问题能力、专业深度 | 多讲方法论与决策逻辑、准备被深挖细节 |
| 高管 | 战略视野、商业敏感度 | 多讲业务理解、行业洞察、跨部门影响力 |

### 2.3 内容来源约束

| 组成部分 | 来源 | 约束 |
|---------|------|------|
| 人设句 | 本文件 §1 生成 | 必须有项目证据 |
| 职业路径脉络 | profile.yml career_stages 的 narrative | 提炼 2-3 个转型节点，不逐条朗读 |
| 专业硬核故事 | 选材确认的项目（弹药库） | 必须真实 |
| 软素质故事 | 弹药库中的跨团队/冲突案例，或用户补充 | 无真实案例则标"需补充"，不编造 |
| 未来方向 | JD 方向 + 用户真实意向 | 与岗位匹配 |
| 引导句 | JD 分析 | 展示对岗位的理解 |

### 2.4 职业路径叙事

从 profile.yml career_stages 按时间顺序提炼，**只讲转型节点**而非逐段朗读：

```
节点识别：stage_label 变化处（如 职业起点 → 关键转型 → 能力深化）
串联方式：每节点半句话，用"从XX到YY"概括，整段不超过 15 秒
```

## §3 口语化打磨（面试成败关键）

简历是**书面语**，面试要**口语**。直接把简历 bullet 背出来是常见失误。

| 维度 | 简历版 | 口述版 |
|------|-------|-------|
| 语气 | 书面简洁 | 口语、有节奏 |
| 细节 | 高度概括 | 有画面感、有具体场景 |
| 节奏 | 匀速罗列 | 有起伏（冲突→解决） |
| 情感 | 中性 | 有真实的困难与感受 |

**口述版模板**：

```
在{项目}中，我面临一个挑战：{核心困难}。
{当时的情况，制造紧张感}
我通过{关键方法}，{具体行动}。
{中间遇到的困难或转折}
最终{量化成果}。这件事让我理解了：{方法论沉淀}。
```

**打磨要点**：
1. 开头用"我面临一个挑战/问题"，而非"我负责了 XX"
2. 中间必须有一个**困难或转折**（无冲突的故事不可信）
3. 结尾给一句可复用的**方法论金句**（记忆点）
4. 数据照实说，不夸大（面试官会追问口径）

## §4 记忆点与钩子设计

**记忆点**（让面试官记住你）：

| 类型 | 方法 |
|------|------|
| 数字冲击 | 用超常规的真实数据（如曝光提升 180%） |
| 对比反转 | 用"预期下降、实际上升"之类的反差 |
| 方法论金句 | 一句可复用的总结（如"分层的核心不是分几层，而是如何精准匹配需求"） |

**钩子**（主动引导面试官追问你准备充分的地方）：

| 位置 | 钩子表达 | 预期追问 |
|------|---------|---------|
| 成果后 | "这个案例让我总结了一套可复用的方法" | "具体说说这套方法？" |
| 过程中 | "当时遇到一个棘手的问题" | "什么问题？怎么解决的？" |
| 数据前 | "在预算受限的前提下" | "怎么做到的？" |

**约束**：每个自我介绍版本至少埋 2 个钩子；钩子指向的内容必须准备充分（钩子是陷阱，引来的追问要能答）。
