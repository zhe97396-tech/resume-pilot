# JD结构化拆解框架

## 核心目标

将一段自然语言的岗位JD拆解为结构化的要求清单，用于：
1. 精准匹配用户经历
2. 提取简历关键词
3. 预测面试考察重点
4. 评估岗位适配度

## 拆解维度

### 1. 硬性要求（Must-Have）

必须满足的门槛条件，不满足通常直接筛掉：

- 学历要求（本科/硕士/985/211/海外）
- 工作年限（最低年限要求）
- 必备技能/工具（如：必须会Python、必须有SQL经验）
- 必备证书/资质（如：CPA、PMP、教师资格证）
- 行业背景要求（如：必须有金融行业经验）

**处理方式**：在适配度矩阵中标记为 ✅/❌，无中间态。

### 2. 核心职责（Core Responsibilities）

岗位入职后要做的事，直接决定简历经历排列优先级：

- 提取每条职责的关键动词和业务对象
- 识别职责的权重排序（排在前面的通常更重要）
- 标注职责对应的技能领域

**处理方式**：与用户经历逐条匹配，标记匹配度（✅已匹配/⚠️部分匹配/❌缺口）。

### 3. 加分项（Nice-to-Have）

非必须但有则优先：

- 优先条件（如：有创业经验优先、有大厂经验优先）
- 特定领域知识（如：了解区块链优先）
- 管理经验（如：有团队管理经验优先）

**处理方式**：在适配度矩阵中标记为 ⭐，有则突出，无则不强调。

### 4. 隐性要求（Implicit Requirements）

JD未明说但实际筛选中考量的：

- 团队规模暗示（"独立负责" → 需要全栈能力；"带团队" → 需管理经验）
- 业务阶段暗示（"从0到1" → 需要创业精神；"优化迭代" → 需要精细化能力）
- 汇报关系暗示（"向CEO汇报" → 需要高层沟通能力）
- 行业暗语（"抗压能力强" → 可能加班多；"拥抱变化" → 组织调整频繁）

**处理方式**：在面试建议中提示用户注意，在简历语态中适当体现。

## JD两层拆解法（行为层解码）

JD 的要求表述通常抽象（如"负责团队""推动项目落地"），直接拿来写简历只会产出空洞的"负责式"表述。需**往下拆两层**，变成可落地、可描述的具体行为。

### 拆解方法

**第一层：抽象要求 → 行为类别**

将JD中的抽象表述映射到具体的行为类别：

| JD抽象表述 | 第一层拆解（行为类别） |
|-----------|-------------------|
| 负责团队 | 团队会议、人员招聘、绩效制定、人员汰换、培养带教 |
| 推动项目落地 | 需求分析、排期制定、资源协调、进度追踪、风险处理 |
| 优化业务流程 | 现状诊断、方案设计、跨部门沟通、流程试点、复盘迭代 |
| 负责数据分析 | 指标定义、数据采集、看板搭建、洞察输出、决策支持 |
| 管理客户关系 | 客户分层、定期沟通、需求挖掘、方案交付、续约维护 |

**第二层：行为类别 → 具体动作 + 证据**

对每个行为类别，进一步拆解为可验证的具体动作，并匹配实绩证据：

```
行为类别（人员招聘）
  具体动作：制定招聘计划 / 优化渠道 / 主导面试评估 / 推进 Offer
  实绩证据：数据（到岗率92%、周期28天）+ 动作（设计3轮面试评估体系）+ 材料（招聘SOP文档）
```

### 核心相关方维度

拆解行为层后，为每个行为匹配**可验证的实绩证据**。第一个核心维度是明确相关方：

很多人简历看似充实但经不起深挖。面试官不会纠结具体怎么做事，而会问"你向谁汇报工作"。因为：

- 旁观过工作、看过别人操作的人，也能把工作内容说得八九不离十
- 但没有真实操盘经验的人，不清楚高层汇报的核心内容、对接的核心人群
- 汇报关系和相关方是验证"真操盘 vs 旁观"的关键

**写法**：在经历描述中自然嵌入相关方信息，一句话即可证明操盘深度。

**示例**：
> "协同财务部门编纂业务预算，向业务BU副总裁直接汇报，制定年度经营方案"

一句话包含：对接部门（财务）、汇报对象（BU副总裁）、工作产出（年度经营方案），证明是全程负责而非单纯参与。

### 行为链条与证据三件套（落地维度）

解码出的行为类别，最终要落到两个写作维度（**详细方法与对比示例见 `references/star-method-guide.md` §STAR进阶**）：

| 维度 | 要求 |
|------|------|
| **行为链条** | 每个 bullet 覆盖「启动→沟通→协调→冲突解决→决策推进→复盘沉淀」中的 2-3 环节，避免只写"负责XX" |
| **证据三件套** | 同一公司经历整体覆盖三层佐证：工作数据（量化成果）+ 具体执行动作（设计了什么/搭建了什么）+ 沉淀材料/可查记录（SOP/制度文件/项目存档） |

> 这两个维度是 JD 解码结果的**落地目标**：解码出的行为类别需按此落到简历表述，而非停留在 JD 原文的抽象词。

## 关键词提取方法

### 提取流程

1. **第一遍扫描**：标记JD中所有技能名词、工具名、方法论名
2. **第二遍筛选**：区分"必备技能"与"提及性技能"
3. **第三遍排序**：按出现频率和在JD中的位置（靠前=更重要）排序
4. **第四遍扩展**：补充同义词和行业惯用表达

### 关键词分类体系

| 类别 | 示例 |
|------|------|
| 技术工具 | Python, SQL, Tableau, Figma, Jira |
| 方法论 | 用户研究, A/B测试, 敏捷开发, OKR |
| 业务领域 | 电商, SaaS, 金融科技, 在线教育 |
| 能力维度 | 数据分析, 跨部门协作, 项目管理, 团队管理 |
| 软技能 | 沟通表达, 逻辑思维, 抗压能力 |

### ATS关键词优化

ATS（Applicant Tracking System）会自动扫描简历中的关键词匹配度：

- 将JD核心关键词自然融入简历正文（不要堆砌在技能栏）
- 使用JD中的原始表述（如JD说"用户增长"就不要写"用户扩张"）
- 技能栏按JD要求的优先级排列
- 避免使用图片格式展示关键信息（ATS无法识别图片文字）

## JD拆解输出模板

```
【岗位名称】XXX
【目标公司】XXX

一、硬性要求
  - 学历：[要求]
  - 年限：[要求]
  - 必备技能：[列表]
  - 必备证书：[列表]
  - 行业背景：[要求]

二、核心职责（按权重排序）
  1. [职责] → 对应技能：[XXX] → 匹配用户经历：[哪段经历]
  2. [职责] → 对应技能：[XXX] → 匹配用户经历：[哪段经历]
  3. ...

三、加分项
  - [加分项1]
  - [加分项2]

四、隐性要求
  - [隐性要求1] → 简历/面试中如何体现
  - [隐性要求2] → 简历/面试中如何体现

五、关键词清单（按优先级）
  Tier 1（必备）：[关键词列表]
  Tier 2（重要）：[关键词列表]
  Tier 3（加分）：[关键词列表]

六、适配度总评
  - 硬性要求达标率：X/Y
  - 核心职责匹配率：X/Y
  - 加分项覆盖率：X/Y
  - 总体适配度：高/中/低
  - 核心优势：[用户最匹配的2-3点]
  - 主要缺口：[用户最不匹配的1-2点]
  - 弥补建议：[如何用可迁移能力弥补缺口]
```

## 特殊JD处理

### 链接型JD

- 用 zhafron-web-search MCP 的 fetch_url（或 markitdown convert_to_markdown）抓取页面内容
- 若为招聘平台链接（BOSS直聘、拉勾等），注意抓取完整内容
- 若页面需要登录才能查看，提示用户提供截图或文本

### 图片型JD

- 用Read工具读取截图
- 提取文字内容后按上述流程拆解

### 简略型JD

- 若JD过于简略（如只有岗位名和一句话），向用户确认是否有更详细版本
- 若无法获取更多，基于行业通用标准推断核心要求，并标注"推断项"
