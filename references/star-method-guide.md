# STAR法则写作指南

## 核心原则

STAR = Situation（情境） + Task（任务） + Action（行动） + Result（结果）

每段工作经历的每个bullet point都应包含完整的STAR结构，但表达上需压缩为1-2行，而非四段式展开。

## 写作公式

**强动词 + 具体行动（含方法/工具） + 量化结果**

示例公式：
- "主导 [什么项目/任务]，通过 [什么方法/工具]，实现 [量化结果]"
- "优化 [什么流程/指标]，从 [原数据] 提升至 [新数据]，提升 [百分比]"
- "搭建 [什么体系/系统]，覆盖 [规模]，使 [指标] 提升 [数据]"

## 四要素详解

### S - Situation（情境）

- 用1句话交代背景，如团队规模、业务阶段、面临的挑战
- 只写对理解行动必要的背景，不写无关信息
- 可省略（当行动本身已足够自解释时）

### T - Task（任务）

- 说明个人承担的具体职责或目标
- 聚焦"我负责什么"，而非"团队做什么"
- 可与Situation合并为一句

### A - Action（行动）

- 这是bullet的核心，占篇幅最大
- 必须以强动词开头
- 写清"怎么做的"：用了什么方法、工具、策略
- 聚焦个人贡献，团队成果用"作为XX参与"过渡
- 1-2句话完成，不展开过程细节

### R - Result（结果）

- **必须包含量化数据**
- 数据类型：百分比提升、金额规模、用户数量、时间缩短、效率提升
- 若无直接业务数据，用间接数据：文档产出量、培训覆盖人数、流程节点减少等
- 放在bullet末尾，作为行动的成果收束

## 强动词参考表

| 类别 | 推荐动词 |
|------|---------|
| 领导类 | 主导、牵头、负责、带领、发起 |
| 建设类 | 搭建、建立、设计、开发、构建 |
| 优化类 | 优化、改进、精简、重构、升级 |
| 分析类 | 分析、诊断、评估、调研、拆解 |
| 推动类 | 推动、推进、落地、实施、执行 |
| 提升类 | 提升、增长、扩大、翻倍、突破 |
| 协作类 | 协同、对接、协调、整合、联合 |
| 交付类 | 交付、上线、发布、完成、实现 |

## 改写对比示例

以下是"流水账 → STAR"改写逻辑的演示（仅用于展示方法，内容为虚构，严禁套用进真实简历）：

**改写前（流水账）：**
> 负责公司电商App的首页改版，和设计团队一起做了一些调整，上线后效果还不错。

**改写后（STAR）：**
> 主导电商App首页改版项目，通过用户行为数据分析重新设计信息流布局，上线后首页点击率提升23%，人均浏览时长增加1.8分钟。

无论岗位类型如何，改写逻辑一致：将"做了什么 + 没量化"的陈述，重写为"主导动作 + 方法/工具 + 量化结果"。不同岗位只需替换业务对象与结果维度，不需套用固定句式。

## 常见错误

| 错误类型 | 问题 | 修正方向 |
|---------|------|---------|
| 流水账 | 只列任务不写成果 | 补充Result中的量化数据 |
| 团队视角 | "团队完成了XX" | 改为个人贡献："主导/负责XX" |
| 无数据 | "效果很好""显著提升" | 必须填入具体数字 |
| 过长 | 一段经历写5-6个bullet | 精简至2-3个最强bullet |
| 堆砌 | 同类经历重复列举 | 合并相似经历，选最强的 |
| 模糊 | "参与了一些工作" | 写清具体做了什么、用了什么方法 |

## 长度控制

- 每段经历：2-3个bullet point
- 每个bullet：1-2行（约30-50字）
- 单条最长不超2行（约60字硬上限）
- 总简历长度：1页（5年以内）或2页（5年以上/资深岗）

## 与JD匹配的优先级策略

1. 提取JD中前5个核心要求关键词
2. 将用户经历按匹配度排序：强匹配 > 弱匹配 > 不相关
3. 强匹配经历：给2-3个完整STAR bullet
4. 弱匹配经历：给1个bullet，突出可迁移能力
5. 不相关经历：一行带过或删除

## STAR进阶：行为链条与证据三件套

STAR是骨架，但要写出"经得起深挖"的简历，还需在Action层补充行为链条，在Result层补充证据三件套。

### 行为链条（Action层扩展）

传统STAR的Action只写"做了什么"，行为链条要求覆盖完整的工作推进环节：

```
组织/启动 → 跨部门沟通 → 资源协调 → 冲突解决 → 决策推进 → 复盘沉淀
```

不必每个bullet都写全链条，但每个bullet应至少覆盖2-3个环节，让招聘方能看出你不是只"参与了某个环节"而是"操盘了完整链条"。

**对比**：

| 单环节表述（弱） | 链条式表述（强） |
|---------------|---------------|
| 参与了预算编制工作 | 主导3部门年度预算编制（启动+沟通），协调资源分配冲突（协调+冲突解决），向VP汇报获批（决策推进），全年执行偏差控制5%以内，沉淀预算管理SOP供团队复用（复盘沉淀） |

### 证据三件套（Result层扩展）

传统STAR的Result只要求"有数据"，证据三件套要求三层佐证并行：

| 佐证层 | 写法 | 示例 |
|--------|------|------|
| 工作数据 | 量化成果 | 招聘到岗率92%、周期缩短至28天 |
| 具体执行动作 | 做了什么动作 | 设计3轮面试评估体系、优化6个渠道投放策略 |
| 沉淀材料/证明人 | 产出什么可查的东西 | 招聘SOP文档、制度文件、项目可查记录 |

同一公司经历不要求每个bullet都写全三层，但整体描述应覆盖这三层。其中"沉淀材料"维度是区分"真操盘"与"旁观参与"的关键——只有真正做过的人才有可查的工作产出。
