# 首次使用引导

> 用途：用户刚装好 skill、数据还没初始化时的**首次接触引导**。`SKILL.md` 的「首次使用」段在数据目录未初始化时指向本文件。
> 本文示例均为**虚构**，仅供理解方法，严禁套用。
> 路径说明：文中 `config/profile.yml`、`references/project-library.md`、`output/` 等都在**数据目录**（由 `scripts/paths.py` 决定：skill 安装 → `~/.resume-pilot/`；克隆为项目 → 项目目录）。

## §1 首次接触协议（agent 执行）

用户第一次提出简历/求职相关请求、且数据目录**未初始化**（无 `config/profile.yml`）时，按顺序做三件事——**不要直接报错、不要编造数据、不要闷头跑脚本**：

1. **先介绍它能做什么**：用 §2 的清单，压成 5-8 行讲给用户（不要整段照搬，不要只念能力名）
2. **给三步开始**（§3）
3. **征得同意后**执行 `python scripts/setup.py`，再按 §4 引导填数据

若数据目录已初始化、但仍是示例数据（`profile.yml` 里姓名是"张三"）→ 提醒先替换，不要硬跑。

## §2 它能为你做什么

| 能力 | 一句话说明 |
|------|-----------|
| 岗位适配分析 | 把 JD 拆开对照你的经历，输出匹配项、部分匹配项与缺口，不写简历 |
| 定制简历 | 按 JD 从你的项目素材里**重新选材 + 重写措辞**，产出针对该岗位的简历 |
| 优化已有简历 | 以你现有的简历为素材基准，按 JD 重写（不从素材库重新选材） |
| 面试准备 | 岗位相关问答、追问预判、自我介绍多版本、反问清单 |
| 投递材料（全流程） | 上面两项一次做完 |
| 换简历照片 | 替换唯一的那张照片，旧图自动备份 |
| 可视化编辑器 | 本地服务 + 浏览器：实时预览、换模板、调字体边距、导出 PDF / 长图 |

## §3 三步开始

1. **初始化**：`python scripts/setup.py`（检查环境 → 装依赖 → 生成数据文件 → 生成编辑器启动器）
2. **填真信息**（两份文件，见 §4）
3. **说第一句话**（见 §5）

## §4 数据怎么填（决定产出质量）

两份文件都在数据目录：

- `config/profile.yml` — 基本信息、职业阶段时间线（**铁律：AI 不改**）、项目分组、优势维度库、工具栈
- `references/project-library.md` — 每个项目的**事实素材**：背景 / 动作 / 量化结果 / 归属

**素材写法对照**（虚构示例）：

| 写法 | 产出效果 |
|------|---------|
| "负责社区产品迭代，数据表现良好" | 平实、面试无法深挖 |
| "社区首页改版（背景：首屏跳出率偏高）→ 调整信息流排序与新手引导位（动作）→ 首屏跳出率下降约两成（结果）" | 有说服力，经得起追问 |

没有精确数据就写量级或相对变化；不必一次填满——**可以先跑一版看效果，再逐步补**。

## §5 第一句话说什么

```
帮我根据这个 JD 定制简历
目标公司：{公司全称}
JD：{粘贴完整 JD}
```

只要适配度分析 → "分析一下这个岗位适不适合我"；只要面试准备 → "帮我准备这个岗位的面试"。
**不必每次跑全流程**：说清你要哪一段即可（意图路由见 `SKILL.md`）。

## §6 其他

- 数据安全、`skills update` 是否影响数据、是否需要联网等 → 见 `README.md`「常见问题」
- 想打开编辑器 → 说"打开简历编辑器"，或双击数据目录里的启动器（见 `ENVIRONMENT.md`）
